# 已安装软件检测与环境诊断设计

## 目标

让 `plan` 和 `install` 在 Windows 与 macOS 上准确识别已有的 Java 开发工具，只安装真正缺失的软件，并明确报告版本、来源、安装状态和环境变量问题。

## 当前问题

- `plan` 没有执行检测，因此所有软件都显示为“待安装”。
- `install` 只按 winget 或 Homebrew 的精确包 ID 判断，无法识别手动安装、IDE 内置或其他发行版的软件。
- JDK 检测绑定 Temurin 21，已有 Oracle JDK 23 仍可能被判定为缺失。
- 项目没有解释安装器决定的安装位置，也没有诊断 `JAVA_HOME`、`PATH` 等配置。

## 检测策略

每个软件包可以声明命令检测规则、最低版本和可选的常见安装路径。检测顺序如下：

1. 执行软件对应的版本命令，例如 `java -version`、`git --version`、`mvn -version`。
2. 解析主版本并验证最低版本要求。JDK 21 及以上均满足 `java-basic`，不限制厂商。
3. 对 IntelliJ IDEA、VS Code、Docker Desktop 等桌面软件检查可执行命令和常见安装路径。
4. 最后使用 winget 或 Homebrew 的精确包 ID 作为补充检测。
5. 任一种可靠检测成功即视为已安装；检测失败但有明确输出时继续尝试下一种方式。

检测结果包含状态、检测来源、版本、实际路径和补充说明。状态分为：

- `已安装`：满足版本要求，安装流程跳过。
- `版本过低`：已安装但不满足最低版本，默认列为待升级。
- `未安装`：所有检测方式均未发现。
- `检测失败`：检测器本身无法正常运行，不允许静默进入安装。

## 命令行为

### `plan`

`plan` 改为只读地执行真实检测，并输出每项软件的版本、来源和最终决定。它不会调用安装命令，也不会修改系统。

```text
- Eclipse Temurin JDK 21：已安装 Java 23.0.2，来源 java，路径 D:\java\jdk\bin\java.exe [跳过]
- Git：已安装 2.51.1，来源 git [跳过]
- Gradle：未检测到 [待安装]
```

### `install`

`install` 复用与 `plan` 完全相同的检测结果，只执行标记为“待安装”或“待升级”的项目。安装后重新检测并输出验证结果。

### `doctor`

`doctor` 在现有包管理器检查基础上增加：

- `JAVA_HOME` 是否存在。
- `JAVA_HOME\bin\java` 与 `PATH` 中的 `java` 是否指向兼容版本。
- Maven、Gradle、Git、Docker 等命令是否可执行。
- 对发现的不一致给出修复建议，但不自动覆盖环境变量。

## 环境变量与安装位置

本阶段不直接写入系统环境变量，也不强制自定义安装目录。winget、Homebrew 和各厂商安装器的能力不同，自动覆盖用户已有配置风险较高。

程序在安装计划和结果中明确说明：

- 安装位置由包管理器和官方安装器决定。
- 安装完成后可能需要重新打开终端。
- `JAVA_HOME`、`MAVEN_HOME`、`GRADLE_HOME` 和 `PATH` 会被重新诊断。
- 如果环境变量仍不完整，输出精确的建议值和配置命令，由用户确认后执行。

后续版本再增加显式的 `configure` 命令，由用户选择是否修改环境变量。

## 代码结构

- `internal/detection`：检测器接口、结果类型、版本解析和组合检测流程。
- `internal/detection/tool.go`：Java、Git、Maven、Gradle、VS Code、Docker 的命令检测。
- `internal/detection/desktop.go`：IntelliJ IDEA 等桌面软件的常见路径检测。
- `internal/platform`：保留包管理器安装命令，并提供包管理器补充检测。
- `internal/service/bootstrap.go`：使用检测结果生成计划并决定跳过、安装或升级。
- `internal/cli`：格式化计划和诊断输出，不承载检测规则。

## 错误处理

- 单个命令不存在属于“未发现”，继续后续检测。
- 命令存在但版本输出无法解析时，记录原始输出并尝试包管理器检测。
- 所有检测器均异常时返回“检测失败”，阻止自动安装，避免错误重装。
- 安装后验证失败时，安装汇总标记失败并写入 `jdb.log`。

## 测试策略

- 单元测试覆盖 Java 新旧版本格式、版本下限和命令不存在。
- 服务测试覆盖已安装跳过、版本过低待升级、未安装待安装、检测失败阻断。
- CLI 测试验证 `plan` 会调用检测器且不会调用安装命令。
- Windows 集成测试使用当前机器上的 Java、Git 等命令验证只读检测。
- CI 中使用假执行器保证 Linux 能运行全部平台无关测试。
